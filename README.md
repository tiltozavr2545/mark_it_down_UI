# MarkItDown UI

> Приложение, которое превращает файл в Markdown полностью на устройстве, без
> интернета, — чтобы результат можно было одной кнопкой скопировать и вставить
> в чат с моделью или в редактор.

## Что это и зачем

«Дай мне этот PDF/DOCX/XLSX в Markdown» — операция, которую делают по многу
раз в день, обычно через сайты-конвертеры, то есть загружая рабочий документ
на чужой сервер. MarkItDown UI делает то же самое на машине пользователя:

1. **Открыть файл** — кнопкой «Выбрать файл», перетаскиванием на окно
   (Windows) или через «Поделиться» из другого приложения (Android).
2. **Посмотреть результат** — сырой Markdown на экране, рядом —
   предупреждения, если что-то в файле не удалось передать (скан без текста,
   объединённые ячейки таблицы, длинный PDF и т.п.).
3. **Забрать** — «Скопировать» кладёт текст в буфер обмена, «Сохранить как
   .md» пишет файл (UTF-8 без BOM). Автоматически в буфер ничего не кладётся —
   только по нажатию, чтобы не затереть то, что там уже было.

Тип файла определяется по содержимому, а не по расширению: файл из
мессенджера без расширения или `.docx`, переименованный в `.pdf`, всё равно
откроется правильно.

**Без интернета — это проверяемое свойство сборки, а не обещание.** В
приложении нет сетевого кода, а на Android у него нет разрешения
`android.permission.INTERNET`: ни приложение, ни одна его зависимость не
могут открыть соединение. Это проверяет CI на каждом коммите. Подробности и
честные оговорки по платформам (на Windows гарантии уровня ОС нет, есть
проверка зависимостей) — в [docs/offline-and-privacy.md](docs/offline-and-privacy.md).

Основа — [microsoft/markitdown](https://github.com/microsoft/markitdown):
оттуда взяты решения о том, как документ ложится в Markdown. Но markitdown —
библиотека на Python и на телефоне не работает, поэтому здесь **две
реализации**: своё ядро конвертации на Dart (работает везде) и настоящий
markitdown, упакованный вместе с Python в «сайдкар» (только на компьютере).
Подробнее — в разделе «Как это устроено» ниже.

## Платформы и статус

Проект идёт по этапам ([план](docs/implementation-plan.md)); сейчас закрыты
этапы 0–4, идёт **Этап 5 — Windows**. Версия — `0.5.0`.

| платформа | статус |
|---|---|
| **Windows** | собирается в CI (GitHub Actions), с сайдкаром; ждёт ручной проверки на живой машине |
| **Android** | работает, проверяется на телефоне автора (APK) |
| macOS | вторичная: код есть, но на машине автора не ставится Xcode — соберётся позже на другом Маке |
| iOS | отложена: машина автора не может собрать сборку, которую примет App Store |
| Linux | отложен: не было запросов |

Почему так и что с этим делать — [docs/future-development.md](docs/future-development.md).

## Что умеет конвертировать

| формат | Windows | Android | чем |
|---|---|---|---|
| `txt`, `md`, `csv`/`tsv`, `json`, `xml`, `html` | ✅ | ✅ | Dart-ядро; текст в Windows-1251 без BOM распознаётся |
| `docx`, `xlsx`, `pptx` | ✅ | ✅ | Dart-ядро (списки, таблицы, сноски, листы, заметки докладчика) |
| `epub`, `ipynb`, `zip` (рекурсивно, с защитой от zip-бомб) | ✅ | ✅ | Dart-ядро |
| `pdf` с текстом | ✅ с таблицами (до 50 стр.) | ✅ без таблиц | сайдкар до 50 страниц, дальше и на Android — Dart-ядро через PDFium |
| `pdf`-скан | ⚠️ | ⚠️ | текста в скане нет — будет предупреждение; OCR — Этап 6 |
| `xls`, `msg` (Outlook) | ✅ | ❌ | только сайдкар |
| изображения, аудио | ❌ | ❌ | распознаются, но конвертера пока нет — Этап 6 |
| `doc`, `ppt` (старый Office) | ❌ | ❌ | не умеет и сам markitdown |

Лимит — 50 МБ на файл (и суммарно на всё распакованное из архива). Что по
какому формату решено и где известные расхождения двух реализаций — в
[docs/format-coverage.md](docs/format-coverage.md).

## Как запустить (пользователю)

Готовые сборки — на странице
**[Releases](https://github.com/tiltozavr2545/mark_it_down_UI/releases/latest)**:
zip для Windows и APK для Android.

### Windows

1. Скачать `markitdown_ui-X.Y.Z-windows-x64.zip` (≈120 МБ) и распаковать в
   любую папку. Ставить ничего не нужно, Python тоже — он уже внутри.
2. Запустить `markitdown_ui.exe`. Всё нужное лежит рядом: `pdfium.dll`,
   папки `data\` и `sidecar\` (Python + markitdown, ≈300 МБ в
   распакованном виде) — папку не разбирать.
3. При первом запуске SmartScreen покажет «Windows защитила ваш компьютер»:
   **«Подробнее» → «Выполнить в любом случае»**. Это потому, что сборка не
   подписана (сертификата пока нет), а не потому, что с ней что-то не так.

Первая конвертация `xls`/`msg`/`pdf` может занять несколько секунд —
Defender проверяет Python при первом запуске.

Сборка из любого коммита (не только релизного) — артефакт
`markitdown_ui-windows-x64` в [Actions](https://github.com/tiltozavr2545/mark_it_down_UI/actions/workflows/ci.yml)
(нужен вход в GitHub).

### Android

1. Скачать `markitdown_ui-X.Y.Z-android-arm64.apk` на телефон и открыть;
   разрешить установку из этого источника, если Android спросит.
2. Нужен Android 6.0+ и процессор arm64 (практически любой телефон последних
   лет).
3. Если приложение уже стояло, собранное не из этого релиза, — сначала
   удалить: сборки пока подписаны разными debug-ключами и поверх друг друга
   не встают (своего ключа подписи ещё нет — Этап 7).

Собрать APK самому — см. «Разработка» ниже.

## Разработка

### Что нужно

- **Flutter 3.32.8** — ровно эта версия (новее требует macOS 14+, а машина
  автора на macOS 12; закреплено и в CI). Проверить: `flutter --version`.
- `make`, `bash`, `curl` — есть на macOS и Linux из коробки.
- Для Android — Android SDK (ставится с Android Studio); для запуска —
  телефон с включённой отладкой по USB.
- Python ставить **не нужно**: сайдкар качает свой, системный не
  используется.
- Никаких `.env`, ключей и аккаунтов: приложению некуда ходить, секретов у
  него нет. Ключи нужны только для подписи релизов —
  [docs/operations.md](docs/operations.md).

### Первый запуск

```bash
git clone https://github.com/tiltozavr2545/mark_it_down_UI.git
cd mark_it_down_UI
make verify
```

`make verify` — это то же, что гоняет CI: `pub get`, проверка
форматирования, `flutter analyze`, тесты приложения и ядра. Заодно он
скачивает библиотеку PDFium (`pdfium/fetch.sh`, ≈4 МБ — в репозиторий она не
коммитится). Зелёный `make verify` — значит окружение собрано правильно.

### Запустить и собрать

```bash
# Android: телефон подключён по USB
cd app && flutter run                      # отладочный запуск
cd app && flutter build apk --release      # APK (сначала make fetch-pdfium)

# macOS (вторичная, нужен полный Xcode)
cd app && flutter run -d macos
```

**Windows локально не собрать** — Flutter собирает Windows-приложение только
на Windows, а разработка идёт на Mac. Поэтому сборка и тесты под Windows идут
в CI на каждом push: джоб `windows` — проверки и `flutter build windows`,
джоб `windows-sidecar` — сборка Python-сайдкара и сверка с Dart-ядром.
Результат — артефакт `markitdown_ui-windows-x64` (см. «Как запустить»). На
Windows-машине собрать можно и руками: `./pdfium/fetch.sh` в Git Bash, затем
`cd app && flutter build windows --release`; Visual Studio нужна 2022 —
Flutter 3.32.8 не знает 2026.

Эмулятор Android на машине автора не запускается (слишком слабая) — всё
проверяется на настоящем телефоне.

### Сайдкар (настоящий markitdown, только на компьютере)

```bash
make sidecar            # → sidecar/dist/<host>/, качает ~сотни МБ
make compare-sidecar    # сверка Dart-ядра с markitdown на всех фикстурах
```

Без собранного сайдкара приложение работает на одном Dart-ядре — всё, кроме
`xls` и `msg`. В `make verify` он не входит именно потому, что тяжёлый.
Версии всех Python-зависимостей закреплены lock-файлами
`sidecar/locks/<host>.txt` (sha256 каждого пакета); обновлять — только
осознанно, `make sidecar-lock`. Устройство, протокол, размеры —
[docs/python-sidecar.md](docs/python-sidecar.md).

### Правила работы в репозитории

Коротко (полностью — в [AGENTS.md](AGENTS.md)):

- перед коммитом — `make verify`; в каждом PR — бамп версии в
  `app/pubspec.yaml` (CI проверяет);
- релиз — тег `vX.Y.Z` на main, дальше всё собирает и публикует
  `release.yml` ([docs/operations.md](docs/operations.md#релиз));
- `core/` не импортирует Flutter — ни в одном файле (проверяет CI);
- новый формат = конвертер + пара фикстур «исходник + ожидаемый Markdown» в
  `core/test/fixtures/`, причём фикстуры нужны «злые»: пустой файл, файл без
  расширения, zip в zip, Windows-1251;
- Markdown собирается только через `core/lib/src/markdown_writer.dart`;
- никаких сетевых зависимостей — CI упадёт сам.

## Как это устроено

```
файл ─► распознавание типа ─► реестр конвертеров ─► Markdown + предупреждения
        (по магическим байтам,   (по приоритету: сначала
         не по расширению)        сайдкар, потом Dart-ядро,
                                  потом общие текстовые)
```

- **`core/`** — ядро конвертации: обычный Dart-пакет без Flutter. Поэтому
  тесты идут быстро (`dart test`), а конвертация работает в отдельном
  изоляте и не замораживает окно. Каждый формат — отдельный конвертер в
  реестре; PDF читается библиотекой PDFium через `dart:ffi`.
- **`app/`** — Flutter-приложение: приём файла, экран результата, буфер
  обмена (`super_clipboard` кладёт `text/plain` и `text/markdown` сразу).
- **Сайдкар** — на компьютере в реестр добавляется ещё один конвертер:
  подпроцесс с упакованным Python и настоящим markitdown. Он идёт первым там,
  где лучше Dart-ядра: `xls`/`msg` (только он) и PDF до 50 страниц (умеет
  таблицы). Если он упал, завис или вернул мусор — результат отдаёт
  Dart-ядро, а в предупреждениях это видно. `docx`/`xlsx`/`pptx` сайдкар
  умеет, но в приложении туда не ходит: Dart-ядро там не хуже, а быстрее в
  десятки раз.
- **Ошибки** — пользователь видит один из трёх понятных случаев («формат не
  поддерживается», «файл повреждён», «превышен лимит»), никогда — текст
  исключения. Частичный результат важнее отказа: PDF, где половина страниц —
  сканы, отдаёт текст остальных.

Подробно — [docs/conversion-pipeline.md](docs/conversion-pipeline.md) и
[docs/client-architecture.md](docs/client-architecture.md).

## Структура репозитория

```
app/                      Flutter-приложение
  lib/src/home_screen.dart      экран: выбор файла, предпросмотр, копирование
  lib/src/file_intake/          диалог, drag & drop, «Поделиться» (Android)
  lib/src/conversion/           запуск конвертации в изоляте
  lib/l10n/                     строки интерфейса (ru, en)
  android/ windows/ macos/      платформенные части
core/                     ядро конвертации — Dart-пакет без Flutter
  lib/src/type_detection/       распознавание типа по содержимому
  lib/src/conversion/           реестр, контракты, конвертеры по форматам,
                                PDFium-биндинги, SidecarConverter
  lib/src/markdown_writer.dart  единственное место сборки Markdown
  test/fixtures/                пары «исходник + ожидаемый Markdown»
  tool/compare_sidecar.dart     сверка Dart-ядра с markitdown
sidecar/                  сборка Python + markitdown для компьютера
  build.sh lock.sh common.sh    сборка, lock-файлы, версии
  run.py                        обёртка: файл → JSON с Markdown
  locks/                        закреплённые зависимости по платформам
pdfium/fetch.sh           качает PDFium (хост, Android, Windows); не коммитится
tool/verify_version.sh    проверка бампа версии в PR
.github/workflows/        ci.yml — verify (Linux), windows-sidecar, windows;
                          release.yml — тег v* → GitHub Release (zip + APK)
docs/                     документация (ниже)
```
