# MarkItDown UI

> Приложение, которое превращает любой файл в Markdown полностью на
> устройстве, без интернета, и сразу отдаёт результат в буфер обмена.

Идея простая: «дай мне этот PDF/DOCX/XLSX в Markdown» — операция, которую
делают по многу раз в день, и делают её через сайты-конвертеры, то есть
загружая рабочий документ на чужой сервер. Здесь конвертация идёт на машине
пользователя, а результат нужен не файлом в «Загрузках», а текстом в буфере —
чтобы вставить в чат с моделью или в редактор.

Основа — [microsoft/markitdown](https://github.com/microsoft/markitdown):
оттуда взяты решения о том, как документ ложится в Markdown. Но markitdown —
библиотека на Python, и на Android/iOS она не собирается, поэтому ядро
конвертации пишется на Dart, а настоящий markitdown подключается подпроцессом
только на десктопе. Почему именно так — [docs/project-brief.md](docs/project-brief.md#3-чем-конвертируем)
и [docs/python-sidecar.md](docs/python-sidecar.md).

## Статус

**Этап 3 закрыт** — [docs/implementation-plan.md](docs/implementation-plan.md).
Каркас, конвейер конвертации и текстовые форматы (Этап 0–1), Office —

Собирается и проверяется живьём пока только Android: на машине автора не

подробнее в [docs/future-development.md](docs/future-development.md#macos-сборка).
PDF на Android стоит ≈6,3 МБ бандла (нативная `libpdfium`) — подробный замер в
[docs/format-coverage.md](docs/format-coverage.md#решения-этапа-3).

## Что значит «без интернета»

Не «мы не отправляем ваши данные», а **проверяемое свойство сборки**: в
приложении нет сетевого кода, и у сборки нет разрешения на сеть. На Android
это означает отсутствие `android.permission.INTERNET` в манифесте — то есть ни
приложение, ни одна его зависимость физически не могут открыть соединение, и
это видно в карточке в сторе. Как проверить на каждой платформе — в
[docs/offline-and-privacy.md](docs/offline-and-privacy.md).

Цена названа там же: половина возможностей markitdown (сканы, подписи к
картинкам, транскрипция аудио) построена на облаке и в продукт не входит.

## Планируемые возможности

- Приём файла четырьмя способами: диалог, drag & drop, системное
  «Поделиться», вставка из буфера
- Определение типа по содержимому, а не по расширению — файл из мессенджера
  регулярно называется `document` без расширения
- Текстовые форматы: `txt`, `md`, `csv`, `tsv`, `json`, `xml`, `html`
- Office: `docx`, `xlsx`, `pptx`, `epub`, `ipynb`, `zip` с рекурсией
- `pdf` — извлечение текста через PDFium; `.xls` и `.msg` — через сайдкар на
  десктопе
- Изображения: EXIF и офлайн-OCR; аудио: метаданные
- Предпросмотр сырого Markdown и копирование одним действием — в `text/plain`
  и `text/markdown` сразу

Что по какому формату решено и чем закрыто — в
[docs/format-coverage.md](docs/format-coverage.md).

## Стек

- **UI:** Flutter / Dart — целевые платформы macOS и Android, но прямо
  сейчас в работе и под реальной проверкой только Android: на машине автора
  не ставится Xcode. Windows, Linux и iOS отложены по той же причине — одна
  машина (см. [docs/future-development.md](docs/future-development.md))
- **Состояние:** Riverpod · **Навигация:** `go_router`
- **Ядро конвертации:** отдельный Dart-пакет без зависимости от Flutter —
  тестируется как `dart test`, уезжает в изолят, при необходимости становится
  CLI
- **Разбор форматов:** `archive` + `xml` (OOXML и EPUB — это zip с XML
  внутри), `csv`, `html` + `html2md`, `pdf` — PDFium через свои FFI-биндинги
  (`dart:ffi`, нативная библиотека не коммитится — см. `pdfium/`)
- **Буфер обмена:** `super_clipboard` — умеет положить несколько
  представлений сразу
- **На десктопе:** настоящий markitdown с упакованным Python, вызываемый
  подпроцессом
- **Чего в стеке нет:** любого сетевого клиента, аналитики, крэш-репортинга

Конвейер конвертации — [docs/conversion-pipeline.md](docs/conversion-pipeline.md),
устройство приложения вокруг него — [docs/client-architecture.md](docs/client-architecture.md).

## Структура репозитория

```
app/                  — Flutter-приложение (UI, платформенные входы, буфер)
core/                 — конвейер конвертации: отдельный Dart-пакет,
                        не импортирует flutter/ — это проверяется в CI
  lib/converters/     — по конвертеру на формат, реестр с приоритетами
  lib/markdown/       — markdown_writer: экранирование, таблицы, заголовки
  test/fixtures/      — пары «исходник + ожидаемый Markdown», включая
                        «злые» файлы (zip в zip, .docx под именем .pdf)
sidecar/              — сборка Python-бандла с настоящим markitdown
                        (только десктоп, см. docs/python-sidecar.md)
pdfium/               — fetch.sh качает libpdfium для хоста и для Android;
                        сама библиотека не коммитится
docs/                 — документация
```

## Запуск локально

```bash
cd app && flutter pub get && flutter run -d macos
```

Никаких `.env` и ключей не нужно: у приложения нет ни одного секрета, потому
что ему некуда ходить. Ключи нужны только для подписи релизных сборок — см.
[docs/operations.md](docs/operations.md).
